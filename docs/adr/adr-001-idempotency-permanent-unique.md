# ADR-001：幂等键语义修订——24h 窗口制改为永久唯一制

日期：2026-10-20 ｜ 状态：已批准 ｜ 影响：contracts/openapi.yaml（描述性修订）

## 背景

stage2 定点 7 采用「幂等 key 24h 窗口内去重」（AI 提出，套用支付网关惯例，人类确认）。
stage5 第 1 步实现时，测试暴露真缺陷：schema 冻结的 `idempotency_key UNIQUE` 是
无时间条件的全局约束，与「24h 过期后可复用」语义冲突——跨窗口重复 key 触发
IntegrityError（代码判「可新建」，数据库判「禁止」）。

## 决策

幂等键改为**永久唯一**：同 key 永远返回首次 task_id，不建新任务。

## 理由

1. key 标识的是业务事件（事件天然唯一），不是「某次 HTTP 尝试」；支付网关 24h 制
   的前提（key 随机生成、空间无限、过期仅为清存储）在本项目不存在。
2. 本系统投递语义为至少一次（宁重复不丢失），窗口制却在入口主动制造隔天重复
   投递，与核心语义自相矛盾。
3. 永久唯一使代码语义与数据库约束完全一致，缺陷类整体消除。

## 修复过程中的次生错误记录

第一版修复曾采用「删除窗口外旧行以释放 key」——将连带删除 attempts 投递历史，
违背 stage3 人类确立的完整可观测原则，写完即自我否决；改用「旧行 key 加
`:expired` 后缀」过渡。随后人类质疑窗口语义本身不合常理，追溯发现窗口为
AI 引入的多余复杂度，遂整体废除窗口制。错误链：引入复杂度 → 制造缺陷 →
修复时险些二次犯错 → 人类掀翻根因。

## 取舍声明（放弃了什么）

放弃「调用方复用 key 提交新事件」的支持：永久唯一制下该行为被去重挡掉。
判定：复用 key 发新事件属调用方错误用法，不应为其复杂化语义；文档写明
「不同事件必须使用不同 key」。
